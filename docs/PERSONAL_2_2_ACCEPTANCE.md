# 2.2.0b1 可恢复清理迭代

基线：2.1 个人增强版（687761c）。本轮目标：补齐缓存清理的可恢复路径，不扩大危险删除范围。

## 已实现

- GUI 默认“备份后清理”，永久清理需显式选择；隔离区选择、记录列表、恢复和独立确认清除。
- CLI `--quarantine`、`recovery init/list/restore/purge`，恢复与清除使用不同确认词。
- 源文件同一句柄读取/备份/删除，整个阶段拒绝写入及替换；隔离区进程间锁覆盖最终原文件删除。
- 备份复制、fsync、SHA-256 读回、DPAPI 清单写入并读回成功后才删除原文件。
- 不修改原清单状态：即使最后删除或进程中断，重新打开仍可检测原路径存在/待恢复/未完成记录。
- 恢复复核当前规则、保护策略、原卷、进程状态、备份内容；临时文件校验后按 Windows
  不覆盖重命名发布。取消/失败保留备份；成功恢复也保留备份。
- 10 GB 默认容量上限、剩余空间检查、同卷拒绝、命名数据流/EFS 拒绝、目录重解析点拒绝。
- `QUARANTINED` 独立执行结果及 recovery_id；汇总历史计入成功，并显示备份后清理数量。

## 本地验收

Windows 11 10.0.26200 x64，Python 3.12.10，PySide6 Essentials 6.11.2。
本地自动测试：144 passed / 4 skipped，含分支覆盖率 86.61%（不含 GUI；GUI 另有 Qt 测试）。

新增测试覆盖：真实复制/句柄删除/恢复/再次打开隔离区、DPAPI 篡改拒绝、同卷拒绝、
配额/空间不足、备份取消、清单写入失败、备份内容损坏、恢复冲突/缺失父目录/规则变化、
受保护目标、并发锁、命名数据流、最终删除失败、恢复取消、CLI 确认及清除。
实际 Qt 异步界面完成选择隔离区→扫描→备份后清理→恢复→独立确认删除备份的端到端测试。
所有文件操作均限定仓库 `tests/.tmp`；未清理用户真实 C 盘，也未执行系统优化命令。

重要：跨卷判断在测试中通过受控接口模拟，数据复制/删除/恢复使用真实 Windows API，
实际发生在同一 E 盘测试目录。没有做真实双盘删除、物理断电/拔盘测试，不能把故障注入
等同于硬件级断电认证。fsync 不能保证故障硬件始终履行持久化语义。

4 个跳过项与 2.1 相同：3 个符号链接创建权限限制，1 个非 Windows 专用测试。
真实 junction 和文件身份/写占用/硬链接安全回归仍包含在完整测试中。

单文件 EXE 已构建，冻结 EXE 的只读启动检查退出码 0；中文 GUI 截图已检查。
便携包含源码、说明、许可和 SHA-256。GitHub PR 的最新工作流结果作为独立云端证据。
本机不进行安装器安装/卸载，由一次性 Windows CI runner 验证。

## 使用边界

此功能仅用于当前规则允许的普通缓存，不适用于重要文档、系统核心文件或完整系统备份。
仅保留内容及修改时间，不完整保留 ACL、创建时间、稀疏/压缩属性。备份内容是明文，
需要私人磁盘目录；清单绑定 Windows 用户，换账号/系统可能不可恢复。规则或原卷变化、
父目录丢失、原文件被应用重新创建时拒绝自动恢复。无自动过期删除。

下一步：真实双盘与断电恢复矩阵、加密备份、可配置配额与保留策略、最小权限 helper；
随后逐应用验证更多缓存规则。保持 Python/Qt 上层，原生接口承担文件句柄和 Windows 数据保护。

参考：[Windows 数据缓冲刷新](https://learn.microsoft.com/en-us/windows/win32/fileio/flushing-system-buffered-i-o-data-to-disk)、
[Windows DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)。
