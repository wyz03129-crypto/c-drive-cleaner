# C Drive Cleaner v2 风险与安全模型

## 1. 不变量

以下规则高于清理率、速度和用户选择：

1. 扫描结果不是删除授权。
2. deny 规则永远优先于 allow 规则。
3. 配置文件和远程内容不能新增可删除根目录或降低风险。
4. 未知路径、未知软件版本、未知链接类型和无法读取的属性一律不自动删除。
5. 用户文档、项目、聊天记录、账号状态、数据库、虚拟磁盘和系统核心文件不得因“体积大”获得删除权限。
6. 每个动作在执行进程中重新校验，不信任 GUI、缓存或旧扫描。
7. Dry Run必须调用相同规划和授权逻辑，但不得到达任何变更 API。
8. 管理员权限不改变风险等级或放宽路径策略。
9. 任何批量动作都必须能够逐项记录结果并在部分失败后安全停止或继续。
10. 实际释放量不能用扫描估算冒充。

## 2. 五级风险模型

### L1 SAFE

明确、可再生、丢失后不会影响用户数据或账号状态的缓存。

- 可默认勾选。
- 仍需一次清理确认。
- 必须有代码内置根目录、文件谓词和最小年龄等限制。

### L2 CAUTION（旧名称 RECOMMENDED 作为兼容别名保留）

通常安全，但会导致首次启动变慢、资源重新下载或缓存重建。

- 默认是否勾选由产品决策明确固定，首版建议不默认勾选。
- 必须显示影响说明。
- 应优先要求相关应用已退出。

### L3 MANUAL（旧名称 REVIEW 作为兼容别名保留）

可能包含恢复数据、离线内容、下载内容或用户可识别信息。

- 永不默认勾选。
- 必须允许查看分类、日期范围和样例。
- 需要针对该类别的二次确认。

### L4 SYSTEM（旧名称 ADVANCED 作为兼容别名保留）

系统级、管理员级或不可轻易逆转的优化，例如组件存储、Windows.old、休眠文件、还原点、Docker/WSL 虚拟磁盘。

- 不走普通文件删除器。
- 只能使用对应官方机制或软件自身机制。
- 每个动作独立确认，展示副作用和可逆性。

### L5 PROTECTED

任何情况下都不能由自动清理执行：

- Windows 核心、启动、恢复、驱动和安装数据库；
- 用户桌面、文档、图片、视频、音乐、下载和云同步原件；
- 浏览器密码、Cookie、书签、历史、扩展和配置；
- WPS/Office 恢复、备份、云文档和版本历史；
- 聊天记录、数据库、项目目录、源码、虚拟机和虚拟磁盘；
- 规则无法证明安全的任何未知内容。

## 3. 规则必须包含的证据

每条可执行规则必须声明：

- 稳定的 `rule_id` 和语义版本；
- 支持的 Windows/应用版本范围；
- 路径来源必须是 Known Folder、Windows API 或可信安装发现；
- 精确授权根目录，不能授权整个用户配置目录；
- 文件/目录谓词、年龄、名称和类型约束；
- 明确排除项；
- 风险等级与理由；
- 执行器类型；
- 清理影响和重建行为；
- 自动测试、Windows 实机测试和回滚/恢复说明；
- 规则失效时的 fail-closed 行为。

仅有“目录名包含 cache/temp/log”不足以进入 L1 或 L2。

## 4. 授权流程

```text
用户选择
→ 重新解析规则
→ 检查规则版本与适用环境
→ 重新发现可信根目录
→ 规范化目标路径
→ 校验卷、范围和 denylist
→ 检查完整路径链及 reparse point
→ 检查文件类型、身份、年龄和规则谓词
→ 检查占用者与所需权限
→ 形成最终动作
→ 执行
→ 校验结果
```

任一环节不确定时结果必须为 `DENIED` 或 `REVIEW_REQUIRED`，不能自动降级成普通删除。

## 5. 删除与竞态控制

- 扫描身份至少包括卷序列号、文件 ID、大小和时间戳；Windows 实现优先使用句柄信息，而不是只使用路径字符串。
- 执行前再次打开并校验目标。
- 不跟随 symlink、junction、mount point 或其他 reparse point。
- 对于不能做到句柄级安全删除的场景，缩小授权根、关闭并发窗口、重新校验并记录残余风险。
- 禁止 `rmtree`、通配符 shell 删除、`takeown`、`icacls` 和任意命令字符串。
- 默认不删除目录；确认目录为空后，可由专用逻辑删除空缓存目录。

## 6. 用户确认规则

| 动作 | 确认要求 |
|---|---|
| L1 批量清理 | 一次汇总确认 |
| L2 | 显示影响后确认 |
| L3 | 查看范围并针对类别确认 |
| L4 | 每项独立确认，必要时 UAC |
| 清空回收站 | 明确展示容量并单独勾选 |
| 关闭普通应用 | 列出应用后再次确认 |
| 不可逆动作 | 默认不提供；若未来提供必须输入专用确认文本 |

## 7. 结果真实性

结果页同时显示三组数据：

1. `Estimated reclaimable`：扫描估算。
2. `Processed allocation bytes`：成功处理目标对应的磁盘分配量。
3. `Observed free-space delta`：清理前后稳定采样得到的可用空间变化。

系统后台活动会影响第三项，因此界面必须注明它是观测值，并在波动过大时降低置信度，不能伪装成精确因果值。

## 8. 隐私

- 默认日志使用规则 ID、错误码和路径哈希，不记录完整用户名和文件名。
- 不联网、不上传、不遥测。
- 导出诊断包前列出将包含的文件，并允许用户选择是否包含脱敏路径映射。
- 扫描数据库仅保存在本机，可在设置中清空。
