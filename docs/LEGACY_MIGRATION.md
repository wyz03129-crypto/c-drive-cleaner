# v1.1 到 v2 迁移边界

## 为什么暂时保留旧源码

根目录下旧 `src/*.py` 保存了已经实现的缓存规则、安全检查和命令行行为。M0 不直接移动或重写这些文件，以便后续逐项建立特征测试，避免安全规则在重构中静默丢失。

旧入口：

```text
python -m src.main
python -m src.main --gui
```

新入口：

```text
python -m cdrive_cleaner
c-drive-cleaner
```

两套入口当前不共享生产逻辑。v2 在 M1 安全内核完成前不提供清理能力。

## 保留并迁移

- deny-first 和代码内置授权根；
- 路径规范化与 containment 检查；
- reparse point 拒绝；
- 文件身份复核；
- Dry Run 不到达变更 API；
- 单文件失败隔离；
- 配置不能扩大授权。

## 不直接迁移

- 串行全量扫描；
- `list(os.scandir(...))`；
- 看到源码扩展名就跳过整个目录；
- Tkinter 页面结构；
- 在程序目录写日志与报告；
- 用逻辑文件大小表示实际释放空间；
- 配置中没有消费者的字段；
- 文档中无法由仓库证据支持的测试结论。

## 删除旧代码的条件

只有同时满足以下条件，才能在独立提交中删除旧模块：

1. 相应 v2 能力已经实现；
2. 正例、反例与安全回归测试通过；
3. Windows 实机或虚拟机验证通过；
4. 迁移对照表确认没有遗漏保护规则；
5. 发布文档和入口已切换到 v2。
